## 2025-03-09 - Accessible Input Associations with React useId

**Learning:** When linking standard HTML form `<input>` attributes like `aria-describedby` to related elements (e.g., error messages and hints) in reusable React UI components, attempting to derive a predictable deterministic `id` from the input's `label` can lead to collisions or missing references, especially when inputs don't supply a label or multiple instances of an identical component appear on screen. React's native `useId()` hook correctly manages safe non-deterministic IDs across components to solve hydration mismatches and collision issues while satisfying ARIA association requirements for screen readers.

**Action:** Always prefer `useId()` as the default fallback for dynamically assigning component ID references (e.g., linking error elements to their descriptive inputs). Additionally, when rendering boolean attributes like `aria-invalid` via React, expressions like `!!error` render cleanly into DOM output (e.g. `'false'` or `'true'`) when asserting against accessibility standard patterns. In UI component tests verifying these auto-generated links, assert strictly against node relationships (e.g., `expect(label).toHaveAttribute('for', input.id)`) rather than hard-coded ID values.
